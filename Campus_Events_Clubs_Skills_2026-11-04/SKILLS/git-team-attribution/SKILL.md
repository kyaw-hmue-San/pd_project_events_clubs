# Skill: Git collaboration and progress attribution
**Use when:** Preparing module branches, handing work to a friend or documenting teammate contributions for lecturer.

## Procedure
1. Read `SPECS/TEAM_COLLABORATION.md` and current `git log`, worktree status and reviewer expectations. Keep each feature on logical branch/PR.
2. If one person wrote the code, credit that person. Invite teammates to add actual validation tests, design tweaks, documentation, accessibility or bug fixes and commit those genuine contributions.
3. Ensure each commit explains a concrete tested change; no mass file reshuffle only to manufacture different authors, no force push.
4. Document PR review comments and integration fixes as meaningful work; merge conservatively after quick checks.
5. Maintain one authentic project progress board with task, owner, branch/commit, evidence, blockers. Preserve change history and user PII confidentiality.
6. If lecturer requests each team member's work, explain the actual split with evidence, rather than artificially dividing a single author's modules.

## Acceptance
The final repository and role review tell the same truthful story about who implemented, tested, reviewed and deployed each piece.
